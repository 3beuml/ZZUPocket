## 二、明确不做的事（写进范围，避免蔓延）

| 不做 | 原因 |
|---|---|
| 电费充值、校园卡转账/消费 | 碰钱，性质变化 + 需存支付密码 |
| **自动抢座 / 定时预约 / 无人值守预约** | 早上 7 点抢座场景；违约惩罚落在用户头上（3 次停用 7 天） |
| 图书馆签到/签离 | **依赖物理闸机刷卡/刷脸，App 做不到** |
| 图书馆"进出馆记录" | 该功能入口存在但 `path:""` 未启用，无接口 |
| 社区/二手/树洞/表白墙 | 与个人工具定位无关 |
| **自建后端中转** | 数据只在设备与学校系统之间流动（合规最优） |
| 多账号 | 个人自用不需要 |
| 5 个校区的完整适配 | 先做"默认校区可切换"，默认主校区 |
| 生物识别锁 | 可选，后期 |

## 附录 B：数据备份方案

### 结论：很好实现，核心逻辑约 100–200 行

### 四种方案对比

| 方案 | 做法 | 优点 | 缺点 | 取舍 |
|---|---|---|---|---|
| **A. JSON 全量导出/导入** ⭐ | SAF 选文件 → 把 Room 各表 dump 成 JSON → 导入时解析并 upsert | 零权限、可控、跨版本能兼容、可手动丢网盘/微信 | 要自己写导入导出（很简单） | **主方案** |
| B. 直接导出 SQLite 文件 | 复制 Room 的 db 文件 | 最完整 | **换表结构后旧备份导入会崩**，要写迁移读取逻辑 | 不做 |
| C. 系统 Auto Backup | manifest 配 `allowBackup` + `dataExtractionRules` | 几乎零代码 | **国内设备基本无 Google 云备份**，不可见不可控 | **附带开启兜底** |
| D. iCal / CSV 导出 | 课表导 `.ics`、学习记录导 CSV | 能导进系统日历、能用 Excel 分析 | 不是备份，是"导出给别人用" | **附带做**（iCal 很实用） |

### 推荐组合

```
主：JSON 全量导出/导入（设置 → 备份与恢复）
附：iCal 课表导出（可导入系统日历）
附：开启系统 Auto Backup 作兜底
```

### 代码骨架

```kotlin
class BackupRepository(
    private val dao: BackupDao,       // 各表全量读/写
    private val json: Json,
) {
    suspend fun export(): BackupFile {
        val payload = BackupPayload(
            schemaVersion = SCHEMA_VERSION,          // 关键
            exportedAt = System.currentTimeMillis(),
            appVersion = BuildConfig.VERSION_NAME,
            courses = dao.allCourses(),
            studySessions = dao.allSessions(),
            libraryReservations = dao.allReservations(),
            energyReadings = dao.allReadings(),
            cardTransactions = dao.allTransactions(),
            settings = dao.userSettings(),
        )
        return BackupFile(json.encodeToString(payload))
    }

    suspend fun import(text: String, mode: ImportMode) {   // MERGE / REPLACE
        val p = json.decodeFromString<BackupPayload>(text)
        val data = if (p.schemaVersion > SCHEMA_VERSION) migrateUp(p) else p
        dao.runInTransaction { dao.upsertAll(data) }
    }
}
```

```kotlin
}
```

### 现在就要做的 3 个数据模型决策（晚了会痛）

1. **`schemaVersion` 常量** —— 导出格式从 v1 开始，以后升级时判断
2. **每张表统一 `updatedAt: Long`** —— 导入时用它决定"谁的更新"，避免合并时覆盖新数据
3. **业务主键要稳定、可跨设备比较**（例如 `study_sessions` 用 UUID 而不是自增 id，否则两台设备合并会撞 id）

### 三条规则

- ⚠️ **绝不导出 token / 凭据**。换机重新登录即可。
- 导入默认 **MERGE（合并）** 而非覆盖，另给一个"清空并替换"的高级选项
- 备份文件**不加密**（里面没有密码/token），但要提示用户自行保管

## 附录 C：UI 组件与库选型

### C1 设计语言：建议 Material 3

| 选项 | 评价 |
|---|---|
| **Material 3（Jetpack Compose）** ⭐ | 官方、最稳、文档最全、组件齐全、支持 **Material You 动态取色**。**推荐** |
| [MIUIX](https://github.com/miuix-kotlin-multiplatform/miuix) | 小米设计语言的原生 Compose 实现，国内审美亲切、大卡片风格（岱宗盒子用的）。但需 composite build 引源码，增加构建复杂度 |
| 第三方 Compose UI 组件库 | 不必要。M3 够用，少一个依赖少一个坑 |

**结论：用 Material 3，需要 MIUIX 风格的地方用自定义 Card/配色即可。**

### C2 逐功能组件对照

| 功能 | 现成组件 | 要自己写的部分 |
|---|---|---|
| 底部 4 tab | `NavigationBar` + `NavigationBarItem` + Navigation Compose | 无 |
| **周课表 7×10 网格** | 没有现成库 | **要自己写**（`LazyColumn` + `Row`，或 `Canvas`）——这是最难的一块 UI |
| 左右切周 | **`HorizontalPager`**（Foundation）⭐ | 无，天然适配手势切周 |
| 今日课表时间轴 | 无现成 | 自己写：`LazyColumn` + 时间刻度 |
| 番茄钟圆环 | `Canvas` + `drawArc`；或 M3 `CircularProgressIndicator(progress)` | 动画用 `animateFloatAsState` |
| **打卡热力图** | **没有现成组件** | **自己写约 100 行**：`LazyVerticalGrid` 7 列 × N 周，双色阶 + "无记录"独立样式 |
| **用电量折线/柱状图** | **[Vico](https://github.com/patrykandpatrick/vico)**（Compose 原生，最现代）⭐<br>或 MPAndroidChart（老牌但 View 体系） | 无 |
| 消费记录列表 | `LazyColumn` + `ListItem` + `stickyHeader` | 无 |
| 日期选择 | M3 `DatePicker` / `DatePickerDialog` / `DateRangePicker` | 无 |
| 下拉刷新 | M3 **`PullToRefreshBox`** | 无 |
| 底部弹详情（课程详情） | M3 **`ModalBottomSheet`** | 无 |
| 分段切换 | M3 **`SegmentedButton`** | 无 |
| 设置页 | `ListItem` + `Switch` + 自己组装 | 无 |
| **桌面小组件** | **RemoteViews + XML**（`AppWidgetProvider`，见 `ui/widget/`） | 布局只能用白名单控件（`<View>`/`<Space>` 会被判 "Class not allowed to be inflated"）；圆角靠 shape drawable，颜色只能靠 `setColorStateList(viewId,"setBackgroundTintList",…)` 刷 tint —— 用 `setBackgroundColor` 会把圆角弄没。曾用 Glance 试过一版，因预览与可变行数两处受限而换回（口径见 `UI与登录设计.md` §2.6） |
| 图标 | `material-icons-extended`（注意体积，R8 会裁剪）或自绘 `ImageVector` | 无 |
| 空状态 / 骨架屏 | 自己画 | 少量 |

### C4 视觉风格（简约好用的具体做法）

1. **一屏一个主任务**——首页顶端永远是"现在在干什么"那张卡
2. **信息一律用 Card 分组**，不要裸排文本
3. **能用 `ListItem` 就不用自定义行**（图标 + 标题 + 副标题 + 尾箭头，四件套）
4. **字号只用 M3 typography 的 3–4 档**，不自创档位
5. **颜色交给 Material You 动态取色**；深色模式跟随系统
6. **不用抽屉导航、不用复杂手势**（唯一手势：切周用 Pager）
7. **动画克制**——只保留番茄钟进度和页面转场
8. **数据新鲜度用小字 + 图标**表达（"数据截至 14:32 ⚠️"），不要弹窗打断
